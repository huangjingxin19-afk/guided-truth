# 被引向的真相

Godot 4.7.2 项目位于 `gotdot/`。游戏从第一章前台开始，可连续玩到第三章《雨棚下的人》结案。

协作制作场景、人物、证物或音效时，从[美术资料](美术资料/README.md)进入，先看当前画风和 102 样板。

## 当前试玩路线

安卓导出目标为 `chapter3-complete-1.0.17.apk`（版本号 18，Android 7.0 及以上，arm64，调试签名）。APK 保存在项目根目录，由 Git 忽略。

### 第一章《上锁的教室》

1. 在主菜单选「开始新游戏」，从前台走到何青面前的柜台边。手机用左下角摇杆移动，电脑点击地面移动。
2. 点右下角“领取委托”（电脑也可按 E）。笔记同时登记“102 调查委托”和“器材交接便笺”。点“展开周闻的便笺”可读完整原文，也可关闭后从笔记回看。
3. 靠近右侧走廊入口，用交互键“前往走廊”。首次到达时故事时间从周四 18:35 推进至 18:40。先打开笔记，确认委托、便笺都仍在。
4. 走到 102 正门前查看封条。正门保持上锁。去走廊右侧选“经外廊去后院”，也可以先到后院再回来补查。
5. 在后院雨棚找推车旁的韩素，查看何青签过的后门授权。查看推车上的随车单，核对谁在什么时候领回了什么。两份证物都能从笔记回看。
6. 韩素同意后，靠近雨棚右侧门口，选“从器材门进 102”。在室内查轮痕，找韩素看第一次过槛，再查脚垫并点“装回脚垫”。找韩素“再推一次”，在笔记里回看“推车复走”。
7. 可以随时关闭笔记或证物页，从器材门原路返回补查。可在装好脚垫后走回走廊，再进 102 继续第二次过槛。

8. 核对封条、后门授权、随车单和推车复走后，靠近 102 右侧的何青，选「向何青提交推理」。两题各选一项。若需要复核，可关闭推理页，打开笔记或回现场补查，再找何青提交。
9. 推理通过后，从长桌右端绕到下层抽屉前，查看报修册和散页，再装入 A01。走到箱边拍清点照片，找桌后的周闻签字。笔记可回看白色补线和签过「已阅」的清点单。
10. 从器材门经后院回走廊，靠近正门选择「回看 102 正门」，看到「第一章完」。

雨棚、角色、推车和报修册采用占位图形。复走及章节收尾用画面和文字呈现。

### 第二章《少掉的一页》

1. 在第一章结尾选择「开始第二章」。关闭结尾后也可回前台找何青进入。时间切到周五 17:20，第一章笔记继续可查。
2. 靠近柜台的手机和便签，登记 16:46 的群聊原图和 16:50 的收页记录。原图可与转发截图对照。绕到柜台右端还可查看登记夹与内袋。
3. 看完两条时间证据后，从走廊绕外廊去后院，经器材门回到 102。先检查旧轮痕，再绕到长桌背后核对 A01。可原路返回前台补查。
4. 在前台请邵宁联系发图人。查过内袋和两处 102 现场后，向何青提交原页判断。对照照片和便签选择先后，再从三张候选页里选出与原图相符的纸页。错项会留在笔记里，可补查后重选。
5. 找邵宁确认收页经过，选择「保存局部并撤图」。再打开柜台手机或笔记，可回看时间、白杯和纸角。
6. 到前台右侧查看改签公告。回收筐边可顺路问周闻收了什么。随后到走廊西梯口，在疏散图旁拍下旧事故说明。
7. 靠近 102 正门，选「查看韩素夜巡」，打开 21:10 收到的消息，最后点「结束第二章」。可关闭结尾，在笔记里回看证据。

详见[第二章开发计划](./第二章-开发计划.md)。新增人物、公告和夜巡近景沿用占位画法。

### 第三章《雨棚下的人》

1. 在第二章结尾点「开始第三章」。若已关闭结尾，靠近 102 正门回看夜巡消息，再打开结尾。
2. 周六 17:50，在走廊找韩素接委托。靠近正门看高窗，右侧仍可核对封条。记下器材架后的人影和黄色卷尺。
3. 经外廊去后院，请韩素开器材门。进 102 后沿长桌后方走到玻璃隔断，选择「查看桌后观察」。
4. 打开笔记，选「对照高窗与桌后」。可单独放大任一张图，再返回并排对照。两张图登记后也可分别从笔记回看。
5. 经后院返回走廊，向韩素说明人影的位置。若选错，可关掉推理页补查后再提交。
6. 到雨棚器材门左侧看门铃旁的留言，回前台在柜台左端核对三张借用卡。选错可重选，也可以退出补查留言。
7. 看柜台右端的《借用物交回通知》，找旁边的韩素确认来访者何时能到。到前台右侧的值班板登记。选「确认赴约」进入 19:25 的 102，确认之前可离开前台补查。
8. 从长桌右端绕到 A01，记录白线、桌脚和敞开的 G03，再从器材门随韩素去雨棚。到长凳旁核对许南带来的谱架，找韩素留存 19:27 签收联。
9. 根据现场、借用卡和签收联向韩素提交归还结论。出现「第三章完」后，可在笔记中回看三章证据。

两个观察近景共用一套占位人物和道具。新增的谱架、G03、纸张和木脚摩擦声用于当前可玩版本。[第三章开发计划](./第三章-开发计划.md)

登记线索、完成剧情步骤或换房后会自动存档。点右上角「暂停」，或在电脑按 Esc，打开暂停菜单后可以继续游戏、立即保存或保存并返回主菜单。Android 返回键和 Esc 会先关闭当前可关闭的笔记、证物或推理页。演出可以暂停并从原处继续。

「继续调查」从上次存档的房间入口恢复，保留笔记和剧情进度。手动保存和自动保存共用同一份进度。已有存档时，主菜单的「开始新游戏」需要确认覆盖。

安卓测试包直接覆盖安装即可保留存档，包名和签名须相同，版本号须递增。卸载或清除应用数据会删除本地存档。自动存档从 1.0.14 开始记录。

## 开发与验证

将 Godot 4.7.2 的命令行程序放入 PATH 后，在项目根目录运行：

```powershell
godot --editor --path gotdot
godot --headless --path gotdot --script ../tests/room_102_inspection.gd
godot --headless --path gotdot --script ../tests/room_102_reenactment.gd
godot --headless --path gotdot --export-debug Android ../chapter3-complete-1.0.17.apk
```

导出使用编辑器中已配置的 JDK、Android SDK、同版本安卓模板和调试签名。不要提交签名文件或密码。

`chapter_one_route.gd` 从主菜单开始，通过地面移动、触控按钮和 E 键验证三章结案。覆盖夜巡结尾重进、雨棚双图对照、借用卡与结案错答、确认前往返、离场留证、签收，以及在主菜单确认或取消重开。默认跳过春册线索并重开第二章结尾，加 `-- --watch-pickup` 验证目击周闻收春册并直接进入第三章的路线。加 `-- --capture` 可在图形模式下保存关键页面到 `.test-runtime/`（先创建此目录）。

`autosave.gd` 用独立进程验证三章续玩、备份恢复、手动保存失败与重试，以及覆盖旧档。在专用于测试的 PowerShell 窗口中运行以下命令，为两个测试分别使用新的数据目录。

```powershell
$env:APPDATA = (New-Item -ItemType Directory -Force ".test-runtime/route-$([guid]::NewGuid())").FullName
godot --headless --path gotdot --script ../tests/chapter_one_route.gd

$env:APPDATA = (New-Item -ItemType Directory -Force ".test-runtime/autosave-$([guid]::NewGuid())").FullName
foreach ($phase in 'first','second','third','resume','backup','reset','damaged') {
    godot --headless --path gotdot --script ../tests/autosave.gd -- $phase
    if ($LASTEXITCODE -ne 0) { break }
}

$env:APPDATA = (New-Item -ItemType Directory -Force ".test-runtime/appointment-$([guid]::NewGuid())").FullName
foreach ($phase in 'first','second','third','appointment-plan','appointment-start','appointment-return','appointment-finish','appointment-complete') {
    godot --headless --path gotdot --script ../tests/autosave.gd -- $phase
    if ($LASTEXITCODE -ne 0) { break }
}
```

102 的共用交互与复走也可通过直接运行 `gotdot/rooms/room_102.tscn` 单独验证。

1.0.8 的后院路线、1.0.9 的摇杆版和 1.0.11 的第二章首段已通过手机试玩。1.0.12 的完整第二章路线已于 2026-11-15 通过手机试玩。
1.0.16 已通过手机试玩，第三章可玩到站位判断。1.0.17 待手机验收。可覆盖安装后从「继续调查」续玩；第三章最短验收路线是从「人影在雨棚」旧档继续，查留言、选卡、登记赴约、记录离场现场，再签收并提交结论。

## 本次结构

- `chapters/chapter_one.gd` 管理第一章时间、目标、复走、推理和结案条件。`InvestigationLog` 保存本局证物和推理记录。
- `chapters/chapter_two.gd` 根据已登记的线索推进第二章并管理故事时间。前台、走廊和 102 复用调查点、笔记和换房，两个章节共用推理表单。
- `chapters/chapter_three.gd` 管理周六的两处观察、借用卡选择、赴约时间、签收和结案。笔记用共用 HUD 展示观察近景和复核证据。
- `rooms/room_transition.gd` 统一切场与新游戏重置。器材门由后院依据授权证物决定是否允许通行。
- `save/save_game.gd` 在同一次操作结束后统一保存章节、证物和房间入口。选择继续调查时先恢复进度，由原房间逻辑还原可交互内容。存档采用本地 JSON 文件和上一份备份。[Godot 官方存读档示例](https://github.com/godotengine/godot-demo-projects/blob/master/loading/serialization/save_load_json.gd)
- `ui/main_menu.tscn` 预留 `BackgroundArt` 和 `TitleArt`。主菜单、暂停和调查 HUD 共用 `ui/investigation_theme.tres`，可在场景和主题中接入正式素材。[Godot 官方暂停菜单示例](https://github.com/godotengine/godot-demo-projects/blob/master/2d/platformer/gui/pause_menu.gd)
- `rooms/investigation_room.tscn` 提供共用移动、调查与 HUD。前台、走廊和雨棚继承后配置本地场景和交互。
- `investigation/*.tres` 保存证物文本和预览。韩素的占位外观由雨棚和 102 共用。

前台委托与证物登记参考了任务状态集中维护的做法。[Quest System 的任务管理实现](https://github.com/shomykohai/quest-system/blob/d1d933c7b1822aceb637e3d6fe3a4814f973c3ee/addons/quest_system/quest_manager.gd)

后院沿用现有的延迟换房方式。换房后由章节状态还原 102 的脚垫和复走进度。[Godot 官方换房示例](https://github.com/godotengine/godot-demo-projects/blob/master/loading/autoload/global.gd)

第二章由首次登记证物触发进度刷新，房间根据章节进度显示当日的调查点。[QuestSystem 分步任务示例](https://github.com/shomykohai/advanced-quest-system-example/blob/main/quests/scripts/base_quest.gd)
